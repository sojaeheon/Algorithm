# Greedy

그리디 알고리즘은 매 순간 가장 좋아 보이는 선택을 하면서 전체 답을 만드는 방법이다. 탐욕 알고리즘이라고도 부른다.

중요한 점은 "지금 좋아 보이는 선택"이 항상 전체 최적해로 이어진다는 보장이 있어야 한다는 것이다.

## 1. 언제 쓰는가

- 매 단계에서 하나를 선택한다.
- 가장 작은 값, 가장 큰 값, 가장 빠른 종료 시간처럼 선택 기준이 보인다.
- 한 번 선택한 것을 나중에 바꾸지 않아도 된다.
- 정렬 후 앞에서부터 처리할 수 있다.
- 현재 선택이 이후 선택의 가능성을 최대한 남긴다.

문제에서 "최소 개수", "최대 개수", "가장 적은 비용", "가능한 한 많이" 같은 표현이 나오면 그리디를 의심해볼 수 있다.

## 2. 그리디가 성립하려면

그리디는 느낌으로 쓰면 위험하다. 보통 다음 성질이 필요하다.

### 탐욕 선택 속성

현재 단계의 최선 선택이 전체 최적해에 포함될 수 있어야 한다.

### 최적 부분 구조

현재 선택을 한 뒤 남은 문제도 같은 방식으로 최적으로 풀 수 있어야 한다.

## 3. 풀이 순서

1. 어떤 기준으로 선택할지 정한다.
2. 그 기준을 위해 정렬이나 힙을 사용할지 정한다.
3. 앞에서부터 선택하며 답을 갱신한다.
4. 왜 그 선택이 항상 손해가 아닌지 확인한다.

## 4. 대표 패턴: 정렬 후 선택

회의실 배정처럼 끝나는 시간이 빠른 것부터 고르는 문제는 대표적인 그리디이다.

```python
meetings.sort(key=lambda x: (x[1], x[0]))

end_time = 0
count = 0

for start, end in meetings:
    if start >= end_time:
        count += 1
        end_time = end
```

끝나는 시간이 빠른 회의를 고르면 이후에 더 많은 회의를 선택할 가능성이 커진다.

## 5. 대표 패턴: 문제를 반대로 보기

어떤 값을 최대화하기 어려우면, 반대로 남기는 것 또는 버리는 것을 최소화해서 풀 수 있다.

예를 들어 동전 자판기 문제는 다음처럼 바꿔 생각한다.

```text
사용하는 동전 수 최대화
= 남기는 동전 수 최소화
```

이런 전환이 그리디 선택 기준을 더 분명하게 만들어준다.

## 6. 대표 패턴: 힙 사용

현재 후보 중 가장 작은 값이나 큰 값을 계속 꺼내야 하면 힙을 사용한다.

```python
import heapq

heap = []

for x in arr:
    heapq.heappush(heap, x)

while heap:
    value = heapq.heappop(heap)
```

## 7. 그리디 증명 방법

그리디 문제에서는 "왜 이 선택이 맞는가"를 설명할 수 있어야 한다.

### 교환 논증

최적해가 있다고 가정하고, 그 최적해의 첫 선택을 그리디 선택으로 바꾸어도 답이 나빠지지 않음을 보인다.

예:

```text
회의실 배정에서 최적해의 첫 회의보다 더 빨리 끝나는 회의로 바꾸어도
이후 회의 선택 가능성은 줄어들지 않는다.
```

### 반례 찾기

그리디 기준이 맞는지 의심될 때는 작은 반례를 찾아본다.

```text
가장 큰 것부터 고르면?
가장 작은 것부터 고르면?
비율이 좋은 것부터 고르면?
```

반례가 쉽게 나오면 그리디가 아니라 DP나 완전 탐색일 가능성이 있다.

## 8. 그리디와 DP 구분

| 상황 | 추천 |
| --- | --- |
| 현재 선택을 바꿀 필요가 없음 | Greedy |
| 이전 선택이 이후 상태에 복잡하게 영향 | DP |
| 모든 경우를 비교해야 함 | 완전 탐색 / DP |
| 선택 기준을 증명할 수 있음 | Greedy |

## 9. 자주 하는 실수

### 기준을 잘못 잡는 경우

회의실 배정은 시작 시간이 아니라 끝나는 시간을 기준으로 정렬해야 한다.

### 그럴듯한 선택을 증명 없이 사용하는 경우

그리디는 반례가 많다. 선택 기준이 항상 맞는지 확인해야 한다.

### 정렬 조건 누락

여러 기준이 필요할 수 있다.

```python
arr.sort(key=lambda x: (x[1], x[0]))
```

### 동점 처리 실수

끝나는 시간이 같을 때 시작 시간, 비용, 번호 등을 어떻게 처리해야 하는지 문제 조건을 확인한다.
